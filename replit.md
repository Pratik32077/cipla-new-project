# Cipla Healthcare Campaign Dashboard

A full-stack enterprise internal web app for Cipla's healthcare awareness campaign. Admins oversee the entire doctor network; managers log their daily field visits with photo and document uploads.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/cipla-dashboard run dev` — run the frontend (port 24444)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`, `SESSION_SECRET`

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5 + express-session
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- Auth: Role-based (admin / manager) via HTTP-only session cookies; bcryptjs
- API codegen: Orval (from OpenAPI spec)
- File uploads: Multer v2 (photos: JPG/PNG max 10MB; documents: PDF/DOC/DOCX max 25MB)
- Excel export: ExcelJS
- Frontend: React + Vite + Tailwind v4 + shadcn/ui + TanStack Query + wouter + Recharts

## Where things live

- `lib/api-spec/` — OpenAPI spec (source of truth for API contract)
- `lib/api-client-react/` — Generated hooks + Zod schemas (Orval output)
- `lib/db/` — Drizzle schema (users + doctors tables)
- `artifacts/api-server/src/` — Express server
  - `routes/auth.ts` — login / logout / me
  - `routes/admin.ts` — dashboard, managers CRUD, all-doctors list, Excel export, daily additions, manager performance
  - `routes/manager.ts` — manager dashboard, my-doctors CRUD, photo/doc upload, Excel export
- `artifacts/cipla-dashboard/src/` — React frontend
  - `pages/login.tsx` — full-page login
  - `pages/dashboard.tsx` — role-aware admin/manager dashboard with Recharts bar chart
  - `pages/managers.tsx` — admin: managers table, add/delete modals, per-manager export
  - `pages/all-doctors.tsx` — admin: all doctors with search/filter/pagination/export
  - `pages/my-doctors.tsx` — manager: own doctors with add modal, photo/doc upload, export
  - `components/layout/` — sidebar + shell layout

## Architecture decisions

- Session-based auth (HTTP-only cookies) — no JWT. `credentials: "include"` on all fetches.
- Doctor uniqueness enforced by `UNIQUE(doctor_name, specialization, city)` constraint.
- File uploads stored locally under `artifacts/api-server/uploads/{photos,documents}/`.
- OpenAPI-first: all typed hooks generated by Orval from `lib/api-spec/openapi.yaml`.
- Multer v2 used (not v1) due to breaking API changes between versions.
- bcryptjs used instead of bcrypt (no native build deps).

## Product

- Admin role: see stats dashboard, manage managers, browse all doctors across the network, export to Excel.
- Manager role: see own stats dashboard, add/edit their doctors, upload photo and consent document per doctor.
- Completion tracking: a profile is "Complete" when both photo and document are uploaded.

## User preferences

- Dark navy enterprise SaaS UI (deep navy sidebar, white/light cards, electric blue primary)
- No emojis in UI
- Role-based access: admins cannot see /my-doctors; managers cannot see /managers or /doctors

## Gotchas

- Run `pnpm --filter @workspace/api-spec run codegen` after any OpenAPI spec change before editing frontend.
- Doctor bulk seeds must use SQL literal VALUES (not parameterized) due to a sandbox limitation with boolean params in batch mode.
- File upload endpoints are NOT in the OpenAPI spec — use raw `fetch + FormData` with `credentials: "include"`.
- Excel export uses `window.location.href` / plain anchor — not an API hook.
